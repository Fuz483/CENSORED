# Пляцоўка — фронтенд

Сервис аренды школьных пространств по часам по всей Беларуси. Демо-каталог содержит
26 помещений; справочник отдельно содержит 30 учреждений образования с адресами из
предоставленного списка. Справочные школы не считаются доступными для аренды, пока
для них не подтверждены помещения, фотографии и расписания. Демо работает на моках.

## Запуск

```bash
cd frontend
npm install
npm run dev        # http://localhost:5173
npm run build      # tsc --noEmit + vite build
npm run preview
```

Нужен Node 20+.

## Демо-вход

Пароль у обеих ролей один — `peremena`. При переключении роли номер телефона
подставляется автоматически.

| Роль в интерфейсе | Телефон | Пароль |
| --- | --- | --- |
| Клиент | `+375 (29) 123-45-67` | `peremena` |
| УО | `+375 (17) 200-00-00` | `peremena` |

Внутренние значения роли остаются `tenant` / `master`; подписи «Клиент» / «УО»
задаются в `src/lib/roles.ts`. Проверка пароля — заглушка в `src/lib/auth.ts`:
её нужно заменить реальным запросом к API.

## Что реализовано

| Экран | Файл | Поведение |
| --- | --- | --- |
| Вход | `src/components/LoginPage.tsx` | Лендинг: герой, недельный график доступности, типы пространств, справочник школ, форма входа с паролем и переключением роли |
| Каталог | `src/components/SearchPage.tsx` | Плоский список с адресом, фильтры УО / тип / время, даты табами, мобильный лист фильтров |
| Подробности | `src/components/ListingDetailsDialog.tsx` | Фото, адрес, тип, вместимость, цена и свободные часы помещения; переход к карте для подтверждённого адреса |
| Бронирование | `src/components/BookingModal.tsx` | Выбор до 6 часов, подтверждение, фейковая оплата, номер брони |
| Мои брони | `src/components/BookingsPage.tsx` | Список оплаченных слотов, сумма, номер для вахты |
| Кабинет УО | `src/components/UoDashboard.tsx` | Свои помещения и брони; ручные брони и добавление пространства с обязательными фото и адресом |

Язык интерфейса переключается между русским и белорусским (RU / BE); выбор
сохраняется в `localStorage`.

Фильтры работают по принципу «пусто = любой»: без УО и типа показываются все
26 пространств. Время задаётся пресетами: «Любое время» (14:00–21:00),
14:00–17:00, 16:00–19:00, 18:00–21:00. Фильтр учитывает час начала слота.
Смена фильтров или даты сбрасывает выбранные часы, чтобы не оплатить скрытый слот.

## Данные и переход на бэкенд

Сейчас всё в памяти, но структура повторяет таблицы:

```ts
// src/lib/types.ts
Listing ↔ нужно согласовать отдельную сущность пространства (адрес, фото, тип,
        вместимость, цена, владелец и школа)
Slot    ↔ booking_table (date, start_time, state, user_id)
User    ↔ user_table    (user_id, name, phone, role, rating)
```

- `src/lib/data.ts` — 26 пространств и генератор слотов: 7 дней × 7 часов × 26 комнат.
  Занятость детерминированная (хэш от `listing.id + date`), на выходных выше.
- `src/state/AppState.tsx` — вход, бронирование, список броней.

Чтобы подключить реальный API, замените реализацию `AppRepository` в
`src/lib/repository.ts`; компоненты не должны знать про HTTP-транспорт.
Для API потребуется согласовать сущность пространства и поля адреса и фотографии.

Текущая схема из плана SmartSpace описывает слоты и пользователей, но не содержит
полного адреса, фотографии, цены, вместимости или владельца пространства. Нельзя
считать, что один ряд `booking_table` достаточен для каталога. Демо-адреса показаны
как «Адрес уточняется», фактические адреса необходимо получить из проверенного источника.

Ожидаемые операции API:

1. Каталог и подробности → `GET /api/spaces` / `GET /api/spaces/:id`
2. Расписание → `GET /api/slots?date=...&from=...&to=...`
3. Бронирование → `POST /api/bookings` с пользователем, пространством, датой и слотами

Типы слотов уже используют `state: 0 | 1` и `userId`, как в `booking_table`.
Поле УО/района тоже нужно связать с сущностью школы или пространства.

## Дизайн-система

Направление — тихий редакционный альманах, а не SaaS с карточками. Подробнее в
`docs/design-direction.md`.

- **Палитра**: бумажный голубой фон, чернильный navy, небесно-голубые акценты данных,
  жжёно-оранжевый только для действий.
- **Шрифт**: Manrope, self-hosted через `@fontsource`.
- **Форма**: радиус 4px у полей и кнопок, hairline-линии вместо теней, почти нет карточек.
- **Сетка**: контейнер 1180px; в каталоге — строки-списки, а не сетка карточек.
  Под заголовками нет декоративных микроподписей; видны адрес и другие данные выбора.
- **Моушен**: только вход модалок и листов, 140–180ms; всё уважает
  `prefers-reduced-motion`.

Сигнатурный элемент — недельная доступность на экране входа: тонкие полосы
«сколько свободных часов осталось», без тепловой карты и иконок.

## Демо-ограничения

- Пароль проверяется локально по двум демо-аккаунтам; настоящей авторизации нет.
- Оплата имитируется, деньги не списываются, данные не уходят на сервер.
- Добавленные помещения, фотографии и брони находятся в памяти и теряются после перезагрузки.
- Адреса сида пока не подтверждены; новые помещения требуют заполненного адреса.
